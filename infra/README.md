# Infra Demo Setup

Automated demo that creates a complete monitoring stack in Azure Kubernetes Service (AKS).

## What Gets Deployed

1. **AKS Cluster** (2 nodes, Standard_DS2_v2) - via Terraform
2. **Prometheus** (metrics collection) - Helm + ConfigMap for scrape configs
3. **Grafana** (visualization) - Helm + ConfigMap for Prometheus datasource
4. **ArgoCD** (GitOps continuous deployment) - Helm + Application manifest
5. **Netflix App** - your demo application (deployed by ArgoCD)

## How It Works

### Prometheus
- Installed via Helm in `monitoring` namespace
- **Configuration**: Generated inline via Helm values (no external prometheus.yml file)
  - Helm creates the `prometheus.yml` config **inside the Prometheus Pod** via the `serverFiles` section
  - Scrape configs defined in install-tools.sh collect metrics from:
    - Kubernetes API server
    - Kubernetes nodes
    - All pods in the cluster
  - Scrape interval: 15 seconds
- Listens on port 9090 inside cluster
- Service type: **ClusterIP** → then patched to **LoadBalancer** for external access

### Grafana
- Installed via Helm in `monitoring` namespace
- Pre-configured with Prometheus datasource via ConfigMap
  - Points to `http://prometheus-server:80` (internal Kubernetes DNS)
  - Allows Grafana UI to query Prometheus for metrics
- Default credentials: `admin / admin`
- Listens on port 3000 inside cluster
- Service type: **ClusterIP** → then patched to **LoadBalancer** for external access

### ArgoCD
- Installed via Helm in `argocd` namespace
- **GitOps-based**: Monitors `kubernetes/deployment.yml` in this repo (infra branch)
- Automatic synchronization:
  - When you update `kubernetes/deployment.yml`, ArgoCD picks it up
  - Automatically deploys the new version to the cluster
  - Perfect for demo: push image → ArgoCD auto-deploys
- Default credentials: `admin / <auto-generated-password>`
- Listens on port 443 inside cluster (HTTP via LoadBalancer)
- Service type: **LoadBalancer** for external access

### Azure LoadBalancer
- When service is patched to `LoadBalancer` type, Azure provisions an actual **Azure Load Balancer**
- Assigns a **public IP address** so you can access from browser
- No need to use AWS or any other cloud—Azure handles it natively

## Prerequisites
- Azure subscription with permissions
- GitHub Secrets:
  - `AZURE_CREDENTIALS`: JSON with `subscriptionId`, `clientId`, `clientSecret`, `tenantId`
  - (Get from: `az ad sp create-for-rbac --sdk-auth`)

## Running the Demo

1. Go to GitHub Actions → Infra Demo workflow
2. Click "Run workflow" button
3. Wait ~20 minutes for resources to deploy
4. Workflow automatically destroys everything after timeout

## GitOps Workflow (ArgoCD)

**The entire deployment is GitOps-based!** This means:
- Your repo is the single source of truth
- ArgoCD continuously watches `k8s/deployment.yaml`
- Any change in the repo = automatic deployment to K8s

### How it works:

```
1. Developer commits to 'image' branch
   ↓
2. GitHub Actions (ci.yml):
   - Builds Docker image
   - Pushes to Docker Hub (e.g., docker.io/user/netflix:v1.2.3)
   ↓
3. Developer updates kubernetes/deployment.yml with new image tag
   (e.g., change image: docker.io/user/netflix:latest → docker.io/user/netflix:v1.2.3)
   ↓
4. Developer commits kubernetes/deployment.yml to 'infra' branch
   ↓
5. ArgoCD detects change in GitHub (via polling or git webhook)
   ↓
6. ArgoCD automatically:
   - Fetches kubernetes/deployment.yml
   - Applies it to the K8s cluster
   - Spins up new Pod with new image
   - Old Pod is terminated (rolling update)
   ↓
7. Netflix app is now running new version in K8s! ✅
```

### Why ArgoCD?
- ✅ Zero-click deployment: push code → auto-deploy
- ✅ Audit trail: every deployment is a Git commit
- ✅ Rollback: just revert the Git commit
- ✅ GitOps best practice: infrastructure-as-code

## Accessing Services

Once deployed, run:
```bash
kubectl get svc -n monitoring
kubectl get svc -n argocd
kubectl get svc -n default
```

You'll see:
```
NAME                 TYPE           CLUSTER-IP    EXTERNAL-IP    PORT(S)
prometheus-server    LoadBalancer   10.0.x.x      <PUBLIC-IP>    80:xxxxx/TCP
grafana              LoadBalancer   10.0.x.x      <PUBLIC-IP>    80:xxxxx/TCP
argocd-server        LoadBalancer   10.0.x.x      <PUBLIC-IP>    443:xxxxx/TCP
netflix-service      LoadBalancer   10.0.x.x      <PUBLIC-IP>    80:xxxxx/TCP
```

Then access:
- **Prometheus**: `http://<PROMETHEUS-EXTERNAL-IP>:9090`
- **Grafana**: `http://<GRAFANA-EXTERNAL-IP>:3000` (user: admin, pass: admin)
- **ArgoCD**: `http://<ARGOCD-EXTERNAL-IP>` (user: admin, pass: <see ArgoCD setup output>)
- **Netflix App**: `http://<NETFLIX-EXTERNAL-IP>:80`

In ArgoCD UI, you can:
1. See the Netflix-App application status
2. View deployment history
3. Monitor pod health and logs
4. Manually sync (trigger redeploy) if needed

In Grafana, Prometheus datasource is already pre-configured, so you can:
1. Go to Explore
2. Select Prometheus datasource
3. Query metrics like `up`, `node_memory_MemAvailable_bytes`, etc.

## Architecture Diagram
```
GitHub Actions (ci.yml)
    ↓ builds image & pushes to Docker Hub
    ↓
Terraform → creates AKS cluster (Azure)
    ↓
install-tools.sh:
  - Installs Helm
  - Helm install Prometheus (generates prometheus.yml inline via values)
  - Helm install Grafana + ConfigMap (datasource)
  - Helm install ArgoCD + Application (watches this repo's kubernetes/ folder)
  - Patches services ClusterIP → LoadBalancer (Azure assigns public IPs)
  - Kubernetes reconciles and creates Azure Load Balancers
    ↓
ArgoCD monitors k8s/deployment.yaml:
  - On every commit → automatically deploys to K8s
  - Rolling updates, health checks, auto-rollback
    ↓
You can access Prometheus, Grafana, ArgoCD via public IPs ✅
```

## Notes
- ArgoCD is free and open-source
- All resources auto-destroy after ~25 minutes (safeguard against Azure costs)
- Script waits for each service to be ready before proceeding
- ArgoCD polls Git every 3 minutes by default (configurable)
